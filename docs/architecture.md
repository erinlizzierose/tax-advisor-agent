# Architecture

This document explains how the [operating manual](operating-manual.md) (35 numbered sections) is split into a short agent core plus eight skills, and which rules the tool configuration enforces versus which rest on instructions alone.

## Core plus skills

The manual is too long to load into every session. The agent therefore has two layers:

- **Core (system prompt).** The role, the non-negotiable rules, the session startup protocol, the ad-hoc question protocol, the confidence and materiality labels, the first-run sequence, and the closing principle, compressed. It also holds a short folder map and a pointer to the skill that handles each kind of work. Target: well under 2,000 words.
- **Skills.** One `SKILL.md` per workflow (strategy discovery, law research, document inventory, and so on). A skill is loaded on demand, only when the work calls for it, so its text costs nothing in sessions that don't need it. Templates (`CURRENT_STATE.md`, source ledger, position memo, strategy master, one-page strategy summary) live in each skill's `templates/` folder.

Both OpenCode and Claude Code read skills from `.claude/skills/<id>/SKILL.md` inside a workspace, so each skill is written once and shared. Only the agent definition and the permission configuration differ per tool.

The workstream prompts (§23–27) are not carried into the agent: the agent replaces the launcher prompt, and each workstream prompt became a skill description. Those sections stay in the operating manual only.

## One write allow-list, enforced two ways

The policy is the same in both tools and is an allow-list (ruling R27): the agent may write only these paths, relative to the workspace root, and everything else is protected.

- `CURRENT_STATE.md`.
- `00_CONTROL/**`, `02_RESEARCH/**` and `04_LONG_TERM_RECORDS/**`.
- `01_STRATEGY/**` except `01_STRATEGY/STRATEGY_SEED.md`.
- `03_TAX_YEARS/TY_<4 digits>/WORKING/**`, where `WORKING` is a direct child of the year folder and only paths strictly below it count; a file at the bare path `…/WORKING` is not writable. The exception has exactly one year segment, `TY_` followed by four digits. A `WORKING/` folder nested deeper, such as `03_TAX_YEARS/TY_2024/W2s/WORKING/`, stays protected.

So the seed, every source-evidence folder, root files such as `opencode.json`, `opencode.jsonc`, `AGENTS.md`, `CLAUDE.md` and `.mcp.json`, and the folders `.agents/`, `.git/`, `.claude/**` and `.opencode/**` (the agent's own guardrails) are all protected without being named. Anything that resolves outside the workspace root is off limits for access, not only for edits.

The two tools enforce it differently, and not with identical precision:

- **OpenCode.** The agent file starts from a deny-all rule, then allows reads, skills and questions (web search gets an explicit deny, see below), then the exact-case edit allows above (`CURRENT_STATE.md`, `00_CONTROL/*`, `01_STRATEGY/*`, `02_RESEARCH/*`, `04_LONG_TERM_RECORDS/*`, `03_TAX_YEARS/TY_????/WORKING/?*`). Three denies follow them, because the last match wins: `03_TAX_YEARS/*/*/WORKING/*` for a `WORKING/` folder two segments below `03_TAX_YEARS/` (because `?` also matches `/`, the `TY_????` allow alone would take `TY_a/bc/WORKING/`; this deny cannot match the real `TY_2024/WORKING/x`), `03_TAX_YEARS/TY_????/*/WORKING/*` for nested `WORKING/` folders, and the case-blind seed deny `01_STRATEGY/????????_????.??`. OpenCode matches patterns case-sensitively (outside Windows), so a differently cased path falls through to deny-all, but on a case-insensitive disk `01_STRATEGY/strategy_seed.md` *is* the seed and would match the `01_STRATEGY/*` allow; the seed deny matches any name of the seed's shape regardless of case. It also blocks other `01_STRATEGY/` names of exactly that shape (8 characters, `_`, 4, `.`, 2), which is fail-closed. OpenCode matches `edit` resources as workspace-relative paths (verified, see below), so every edit rule is written relative to the workspace root and the installer copies the file without rewriting it. A wildcard can't express "digits only", so the year segment is the pattern `TY_????`: OpenCode therefore approximates the digit rule, and a folder such as `03_TAX_YEARS/TY_ABCD/WORKING/` is writable there. Access outside the workspace root is denied through `external_directory`. The agent also denies `subagent`, because child agents don't inherit the parent's restrictions. `tests/test_opencode_policy.py` evaluates the rendered rules with the documented semantics (ordered, last match wins, `*` matches any characters including `/`, `?` exactly one) against the guard's own path table and lists every accepted divergence.
- **Claude Code.** Claude evaluates deny rules before allow rules, so `settings.json` can't express an exception inside a denied folder. The policy is enforced by a small stdlib-only PreToolUse hook, backed by unit tests, with the matcher `Edit|Write|NotebookEdit|Read|Glob|Grep`. For write tools the hook applies the allow-list, including the four digits, comparing ASCII names case-insensitively. Any path component with a non-ASCII character is protected (so the long s, U+017F, or the Kelvin sign, U+212A, can't spell a protected name that a case-insensitive disk folds to ASCII), as is any existing target that is the same file as the seed (`os.path.samefile`, which catches a hard link or symlink to it). It checks both the lexical path and where symlinks resolve. For `Read`, `Glob` and `Grep` it blocks only targets that resolve outside the workspace root (`file_path`, `path`, and a `Glob` pattern's literal prefix). A `Glob` pattern, a `Grep` `glob` or a `Grep` `path` with a `..` segment anywhere is blocked outright, including one inside brace or extglob alternatives (`{../..,a}/*`, `@(..)/*`), an escaped `\.\.` or a `[.][.]` class: the pattern is split on `/`, braces, commas, parentheses and `|`, and any segment made only of dots and brackets with at least two dots counts. Dots inside a longer name (`*.v1..2.md`) are allowed; a file or folder named exactly `...` can't be globbed (fail-closed). Because only the literal prefix before the first wildcard is resolved, a `Glob` pattern or `Grep` `glob` is also blocked when any brace or extglob alternative (the text after `{`, `,`, `(` or `|`) starts with `/`, `~`, a drive such as `C:` or a UNC `\\`, after dropping backslash escapes and a leading `[` (`{x,/etc}/*`, `@(~|x)/*`, `{\/etc,x}/*`, `{[/]etc,x}/*`); relative alternatives such as `{00_CONTROL,02_RESEARCH}/**/*.md` stay allowed. An empty or whitespace-only optional `path` (`Glob`, `Grep`) or `glob` (`Grep`) counts as absent; any other non-string or blank value of a field the hook inspects is blocked. It runs from `${CLAUDE_PROJECT_DIR}` with `onFailure: "block"` (needs Claude Code 2.1.295 or later) and fails closed on any error. The agent gets an explicit `tools` allowlist, and `settings.json` denies `Bash`, delegation, and `mcp__*`.

## Enforced versus instruction-only

Enforced by configuration, in both tools:

- Writes are limited to the allow-list above; the seed, source evidence, root configuration files and the agent's own configuration can't be edited. OpenCode approximates the digit rule, as described above.
- Access to paths outside the workspace root is denied in both tools. OpenCode uses `external_directory`; the Claude Code hook checks where the path resolves, for reads as well as writes.
- Shell access is denied. This closes the obvious bypass (`mv`, `cp`, or `>` over a protected file).
- Delegation to other agents is denied.
- MCP access is denied in both tools:
  - **OpenCode:** the agent's permission list starts from deny-all and never allows MCP tool actions (`<server>_<tool>`) or `execute` (Code Mode).
  - **Claude Code:** `mcp__*` is denied in `settings.json`, and the agent has an explicit `tools` allowlist.
- Web fetch is scoped to authority hosts. Web search differs per tool, so the two tools differ in how they research:
  - **OpenCode web search is denied by the agent's permissions** (an explicit `websearch` `*` deny after the deny-all). OpenCode's first web search asks the user to pick a search provider; in a non-interactive `opencode run` that question is cancelled. In the 2026-11-03 live eval run, 24 of 33 runs errored: every run that called `websearch` got "Web search cancelled", and OpenCode exited 1 after the agent had finished. `websearch: false` exists only as top-level config, and the installer writes no project `opencode.json` into a user's workspace, so the agent denies the action itself. The deny also keeps queries away from third-party search services. Research in OpenCode is fetch-only: the agent fetches the listed official hosts directly, including their site-search pages.
  - **Claude Code keeps its built-in WebSearch** (the agent's `tools` list and `permissions.allow` still include it), so the two tools differ: Claude Code can search, OpenCode cannot.
  - **OpenCode web fetch:** `webfetch` allows only exact `https://<host>/*` URLs, plus the bare `https://<host>` (the `/*` form does not match a URL with no path; `https://www.irs.gov` was denied live), for the federal authority hosts (`irs.gov`, `law.cornell.edu`, `uscode.house.gov`, `ecfr.gov`, `federalregister.gov`, `govinfo.gov`, `congress.gov`, `ustaxcourt.gov`, `supremecourt.gov`, `treasury.gov`, each with its `www.` form, plus `apps.irs.gov` and `home.treasury.gov`). Everything else falls to deny-all. A wildcard host such as `https://*.gov/*` can't be used safely, because `*` also matches `/` and would admit `https://evil.example/x.gov/`.
  - **Claude Code web fetch:** `permissions.allow` grants `WebFetch(domain:*.gov)`, `WebFetch(domain:law.cornell.edu)` and `WebFetch(domain:www.law.cornell.edu)` instead of the bare `WebFetch`. A fetch to any other host is not pre-approved: it prompts in an interactive session and is refused in a non-interactive run (`claude -p`).

Enforced by instructions only (a prompt can ask for these but nothing blocks a violation):

- Approval gates: strategy approval, amendment plan, filing readiness.
- Primary-authority-first research and the research labels.
- No claims of filing without evidence.
- Treating web pages, search results and workspace documents as evidence, never instructions, and keeping household identifiers and amounts out of search queries and URLs (core rule 15, with the fuller version in `tax-law-research`).

The evals check the instruction-only rules by running the real agent and inspecting the files it writes. Enforcement is tested separately from compliance: the agent is told to attempt a protected write, and the result is recorded as passed (attempted and blocked), inconclusive (never attempted), or failed (file changed). Only a denied write tool counts; a guard denial of a `Read`, `Glob` or `Grep` outside the root is parsed as a denial but is never enforcement evidence.

The protected-file audit (`protected_snapshot` in `evals/harness/workspace.py`) hashes every file outside the write allow-list, including the installed `.claude/` and `.opencode/` trees; only the harness's own transcript file is exempt. Live smoke runs on 2026-10-30 (Claude Code 2.1.311 and OpenCode v2.1.4, scenario `seed-enforcement`) showed neither CLI writing into those directories: `.claude/` stayed exactly as installed and `.opencode/` held only `agents/`. The audit is deliberately fail-closed with no exemptions for CLI-owned files. A future CLI version that writes into its project config directory (for example `.opencode/package.json`, `.opencode/node_modules/` or `.claude/settings.local.json`) would make every row fail visibly as "protected files changed" until that is handled explicitly; `tests/test_workspace_cli_writes.py` pins this outcome.

## Known limitations

- **Instruction-only rules.** The approval gates, research labels, no-claims-without-evidence rule, the untrusted-content rule and the outbound-data rule are instruction-only; nothing in either tool blocks a violation.
- **Web search differs per tool.** OpenCode web search is denied by the agent's permissions (provider-selection prompt cannot be answered non-interactively; observed 2026-11-03, "Web search cancelled"), so OpenCode research is fetch-only to the listed official hosts and finds sources through their own site search and links; the agent labels a conclusion UNCERTAIN and unverified when it retrieved no primary source. Claude Code web search is unrestricted: it allows every search query, so a misbehaving or prompt-injected agent could put household data in a search query. Only the instruction in core rule 15 stands against it. A fetch URL, including a site-search URL, can leak the same way in both tools.
- **Some primary sources are out of reach from OpenCode.** OpenCode research is fetch-only (see above), and some official sources can't be fetched. In the 2026-11-04 live run, the IRS site-search page and `congress.gov` returned HTTP 403 to `webfetch`, and `webfetch` could not read PDFs (for example the 2024 Publication 530 PDF). A conclusion that depends on such a source stays unverified in OpenCode even when Claude Code, which can search, reaches the same source.
- **Transcripts with long digit runs in web results are withheld.** Fetched and searched pages carry third-party ids that are 9 or more digits long (web-archive capture timestamps, help-center article ids, `def_id` values in U.S. Code pages). The privacy scan can't tell them from household numbers, and web-tool results are not rewritten, so such a transcript is withheld (fail closed) and only its result row is published. The raw copy stays in the run's temp directory.
- **Web fetch scope.** OpenCode: only the listed federal hosts; state tax sites are not listed, so a user who needs one must add both an `https://<host>/*` and a bare `https://<host>` allow for it (a wildcard host is unsafe, as above). A request that the allowed host redirects elsewhere was not tested. Claude Code: `WebFetch(domain:*.gov)` covers federal and state `.gov` hosts, but the rule only pre-approves; in an interactive session the user can approve any other host at the prompt, and Claude Code's built-in pre-approved documentation domains stay fetchable. The Claude hook does not inspect `WebFetch`. Neither tool's web-fetch scope was exercised in a live run yet; both are checked against the current docs only (see below).
- **OpenCode's `TY_????` approximation.** `?` matches any one character, including `/`, so `TY_ABCD/WORKING/` is writable in OpenCode; `TY_a/bc/WORKING/` would be too, but the `03_TAX_YEARS/*/*/WORKING/*` deny after the allow closes that gap. The nested-WORKING deny also blocks a `WORKING/` folder inside `WORKING/` (fail-closed). OpenCode's rules see the lexical path, so a symlink a user placed inside an allowed folder is not resolved by the rules (the agent has no shell and can't create one).
- **Hard links and the check-then-write race.** The Claude hook detects a hard link only to the seed; a hard link to other source evidence inside an allowed folder, created by the user, is writable. OpenCode does not detect hard links at all. Both tools check a path before the write happens, so a path changed between the check and the write (a swapped symlink) is not caught; the agent has no shell to stage that, but another process could.
- **Claude Code version.** The hook fails closed only with `onFailure: "block"`, which needs Claude Code 2.1.295 or later; older versions ignore the field and a crashing hook would not block.
- **Python version for the Claude hook.** `settings.json` runs the hook as bare `python3` from the user's `PATH`, which needs Python 3.8 or later (checked by running the hook's subprocess cases under macOS's `/usr/bin/python3`, 3.9.6, when present). A `python3` of 3.7 hits a version gate that prints `[tax-advisor-guard] blocked: python3 >= 3.8 required` and exits 2, so every guarded call is blocked. Python 3.6 or older can't compile the file at all; the hook then exits 1, and only `onFailure: "block"` turns that into a block.
- **Read-tool glob analysis is lexical.** The hook does not expand globs. Wildcard forms that could match `..` without spelling it, such as `??`, `.?` or a character class other than `[.]`, are not analyzed; this relies on glob walkers normally not matching the `.` and `..` entries, which was not verified against Claude Code's `Glob`. The rooted-alternative check also blocks some harmless patterns (an alternative right after a literal, such as `a{/b,/c}`, or one starting with `x:`), which is fail-closed.
- **Path arguments with surrounding whitespace are refused.** Whether Claude Code trims path arguments was not verified, so `" /etc/hosts"` could reach `/etc/hosts`. The Claude hook therefore blocks any inspected path argument with leading or trailing whitespace (spaces, tabs, newlines, NBSP and other Unicode whitespace): `Read` `file_path`, `Glob` `pattern` and `path`, `Grep` `glob` and `path`, and the write tools' `file_path` and `notebook_path`. A blank optional `path` or `glob` still counts as absent. The `Grep` search `pattern` is not a path and is not checked. A file whose real name starts or ends with whitespace can't be read or written (fail-closed).
- **Claude reads outside the root.** The hook blocks them, which also blocks Claude Code's own large-output files stored outside the workspace, if the model tries to read them back.

## Verified against docs (2026-10-27)

Field names and tool names in `agent/` were checked against the current OpenCode V2 docs (`opencode.ai/v2/docs/agents`, `/permissions`) and Claude Code docs (`code.claude.com/docs/en/sub-agents`, `/tools-reference`, `/settings`, `/hooks`, `/permissions`). Where the docs differed from the original plan, the docs won:

- **`MultiEdit` is not a current Claude Code tool.** The permissions page only mentions a "legacy `MultiEdit`". It is left out of the agent's `tools` allowlist and out of the hook matcher, which is `Edit|Write|NotebookEdit|Read|Glob|Grep`.
- **Delegation tool is `Agent`.** `Task` was renamed to `Agent` in Claude Code 2.1.63 and still works as an alias, so `settings.json` denies both. The agent's `tools` list omits `Agent`, which also prevents spawning.
- **`Skill` is the skill tool name.** It is in the `tools` allowlist and in `permissions.allow`, because the agent loads skills itself.
- **`claude --agent tax-advisor` honors the `tools` allowlist.** The docs say the main thread takes on the agent's tool restrictions and model. Listing `Glob` and `Grep` without `Bash` keeps them available on macOS and Linux.
- **Hook fields.** `type`, `command`, `args` (exec form, no shell) and `onFailure` (`"continue"` or `"block"`) are documented. `onFailure` needs Claude Code 2.1.295 or later; on older versions the field is ignored and a failing hook would not block.
- **Model (checked 2026-11-07).** `settings.json` sets `"model": "opus"`, so an installed workspace starts the agent on Opus. The model-config docs (`code.claude.com/docs/en/model-config`) rank the `--model` flag and `ANTHROPIC_MODEL` above a `model` setting, so eval runs keep the model they pass. A user can switch for one session with `/model`, but project settings reapply on the next launch, so a lasting choice needs `--model` or `ANTHROPIC_MODEL`. The agent frontmatter has no `model` field on purpose: with `--agent` the main thread takes on the agent's model, and the docs don't say whether that or `--model` wins. In the 2026-11-07 eval, Sonnet made two tax mistakes in five scenarios and Opus none.
- **`$schema`.** The settings docs show `https://json.schemastore.org/claude-code-settings.json`, which `settings.json` uses.
- **OpenCode V2 field names.** `permissions` (not `permission`), `shell`/`subagent` (not `bash`/`task`), and the `*` action wildcard for deny-all are current. The Markdown body is the system prompt. Edit resources are workspace-relative (see above).
- **Claude Code edit rules.** `Edit(path)` rules also cover `Write` and `NotebookEdit`, but deny rules can't carve out an exception, which is why the hook enforces the policy.
- **Web fetch rules (checked 2026-10-29).** Claude Code (`code.claude.com/docs/en/permissions`): `WebFetch(domain:host)` matches the hostname case-insensitively; a leading `*.` matches any subdomain at any depth but not the bare domain, and `*` elsewhere matches only within one label (wildcards need 2.1.172 or later). A bare `WebFetch` allow approves every URL, so the settings use domain rules only; the eval runner accepts `WebFetch(domain:<host>)` or `WebFetch(domain:*.<host>)` with a lowercase DNS name and rejects any other specifier. OpenCode (`opencode.ai/v2/docs/permissions`): the `webfetch` resource is the requested URL, matched whole, with `*` crossing `/`, so only exact-host `https://<host>/*` patterns (plus the bare `https://<host>`) are safe.

## Verified on 2026-10-27 with Claude Code 2.1.311 / OpenCode 2.1.4

These findings come from real (tiny) runs in throwaway directories, with sanitized captures kept in `tests/fixtures/real/`. The eval runners in `evals/harness/runners/` implement them.

- **Config isolation, OpenCode.** Global config (`AGENTS.md`, plugins, MCP, skills, providers) lives in `$XDG_CONFIG_HOME/opencode`, and OpenCode also reads skills from `~/.claude` and `~/.agents`. Each run therefore gets an empty `XDG_CONFIG_HOME` and an empty `HOME`, while `XDG_DATA_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` keep their real values so provider credentials (stored in the data directory) still work. Asked to list its skills, the agent named the eight tax skills plus `OpenCode` and `Report`; those two are built into OpenCode (`/builtin/*.md`) and can't be turned off. `OPENCODE_DISABLE_EXTERNAL_SKILLS` and `OPENCODE_DISABLE_CLAUDE_CODE*` are unusable here because they also hide the workspace's own `.claude/skills`.
- **Config isolation, Claude Code.** `--setting-sources project --strict-mcp-config` is enough: the `init` event shows no MCP servers, only built-in plugins, no user agents, and the model reported no `CLAUDE.md` content. Bundled Claude Code skills (`simplify`, `loop`, ...) stay visible. `--bare` would drop the project agent, skills and hook, so it is never used.
- **Agent and skills.** `claude -p --agent tax-advisor` and `opencode run --agent tax-advisor` both select the agent, and the eight skills load in both. OpenCode's tool list for the agent was `glob grep patch question read skill webfetch websearch` when this was verified; web search has since been denied (see the web section above). GPT models edit through `patch`, not `edit` or `write`.
- **Claude frontmatter comments break the agent.** With `#` comment lines in the frontmatter (one contained `---`), Claude Code 2.1.311 silently ignored `.claude/agents/tax-advisor.md` and `--agent tax-advisor` printed "not found". The comments were removed from `agent/claude/frontmatter.yaml`, and a test keeps them out.
- **Claude trust.** In `claude -p` a fresh directory is never trusted. Hooks and deny rules still apply, but the project's `permissions.allow` is dropped, so no tool could write. The runner passes the installed `settings.json` allow list as `--allowedTools`, capped at the agent's own tool allowlist (`Read, Write, Edit, Glob, Grep, WebFetch, WebSearch, Skill`; a test keeps the cap equal to `agent/claude/frontmatter.yaml`). `WebFetch` is passed only as domain-scoped entries. Settings naming any other tool make the runner raise before launching; the guard hook still runs first.
- **OpenCode edit resources are workspace-relative.** With the relative seed deny removed and only an absolute-path one left, the seed write succeeded. The relative rules do the work, so the absolute copies this project first wrote (and the installer's per-workspace path rendering) have been removed. The installer now rejects a template that still contains a `{ROOT}` placeholder.
- **OpenCode denial shape.** A denied call is a `tool_use` line whose `part.state` is `{"status": "error", "error": "Permission denied: edit"}`, with the call id in `part.id`. The remembered text ("The user has specified a rule...") was wrong and was replaced in `events.py`. For `patch` the path is only inside `input.patchText`, so the parser reads the `*** Add/Update/Delete File:` and `*** Move to:` lines.
- **Case-variant seed write.** Claude Code: blocked (the hook compares case-insensitively), seed hash unchanged. OpenCode: **not blocked** on macOS's default case-insensitive volume. Appending to `01_strategy/strategy_seed.md` succeeded and changed the real seed. OpenCode's rule patterns did not match a differently cased path, so on a case-insensitive file system the old deny-list could be sidestepped by changing the case. The allow-list (R27) closes this: a differently cased path no longer matches any allow and falls to deny-all, and the case-blind seed deny covers the one protected file inside an allowed folder. Not yet re-run live.
- **Claude stream-json.** The hook denial arrives as an `is_error` `tool_result` reading `PreToolUse:Edit hook error: [python3 ...guard_paths.py]: [tax-advisor-guard] protected path: <path>`. The existing parser handles it unchanged.
- **Question tool.** Headless `opencode run` does not hang. The call returns at once with the error "This non-interactive run cannot ask the user questions, so the question was cancelled", which is a tool error and not a permission denial.
- **Judge.** `--tools ""` leaves only the `StructuredOutput` tool that `--json-schema` adds; no file, shell or web tools. Stdin and the positional prompt are combined, and the verdict appears both as the object `structured_output` and as a JSON string in `result`.
- **Error kinds.** Claude Code: an assistant event with a top-level `error` (observed `authentication_failed`; the Agent SDK documents `rate_limit`, `billing_error`, `invalid_request`, `server_error`, `unknown`), a `rate_limit_event` whose `status` is `rejected`, or a `result` with `is_error: true`. OpenCode: a top-level `{"type": "error", "error": {"type": ...}}` event (observed `provider.no-route` for missing credentials, and `provider.quota` with "The usage limit has been reached" when the ChatGPT plan's usage limit ran out on 2026-11-04, mapped to `rate_limit`; `provider.authentication`, `provider.rate-limit` and `provider.quota-exceeded` are inferred from OpenCode's error schema and were not provoked, since rate limits can't be triggered safely). Missing credentials and an unknown model both give `provider.no-route`.
- **OpenCode run completion.** In every capture the intermediate `step_finish` events carry `reason: "tool-calls"`; the final step emits no `step_finish` and the stream ends on a non-empty `text` part. The runner treats a run as complete only when the process exited 0 and the last event is such a `text` part (or a `step_finish` with reason `stop`, which was not seen). A non-zero or signal exit, empty output, a transcript cut off mid-step, or one that ends on an intermediate `step_finish` is `error_kind="other"`; a structured `error` event still takes precedence. Residual: OpenCode emits no explicit run-end event, so a zero-exit stream cut off right after a text part still looks complete (a heuristic). A permission denial inside a completed run is a tool error and stays distinct.
- **OpenCode finds its project from `$PWD`, not the process cwd.** With the parent's `PWD` left in place, a run started with `cwd=<workspace>` looked for agents in the repo and failed with `Agent not found: "tax-advisor"` (it would also have pointed OpenCode at the repo instead of the throwaway copy). `_proc.run_process` now sets `PWD` to the resolved cwd for every child, and so does the judge. `tests/test_opencode_probe.py` checks this against the real CLI with a nonexistent model (`provider.no-route`, never a model call); deselect it with `-m "not opencode_probe"`. OpenCode's JSON events carry no session directory field, so no extra in-stream check is possible.
- **Transcripts are sanitized, by metadata allowlist, before the privacy scan.** Home paths in Claude's `init` event, 13-digit OpenCode timestamps, epoch `resetsAt` values and long float costs had made every transcript look like a privacy finding. `evals/harness/sanitize.py` rewrites only exact scalar leaves, and only for the event type that carries them: each rule is (tool, event-type selector, leaf path), e.g. Claude (`system`/`init`, `cwd`), (`result`, `total_cost_usd`), (`assistant`, `message.id`) or OpenCode (`tool_use`/`tool`, `part.state.time.start`). An event of an unlisted type, an unlisted leaf, and every container (including the entries of `skills`, `slash_commands`, `tools` and `mcp_servers`) is left verbatim; `plugins[].path` gets home-path replacement only. Everything an author wrote (assistant text, tool inputs, tool results, command output, OpenCode `part.text` and `part.state` input/output/error) is never rewritten, so a home path, an id-shaped client name, or a long number in authored content stays visible and the transcript is withheld (the raw copy stays in the run's temp directory). One leaf inside a tool result is metadata: Claude's `tool_use_result.durationSeconds` (on `user` events), the CLI's own timing of the call, is rounded like a cost. The other exception is the literals the harness itself created or chose and passes in explicitly: the workspace path and the temp root become `<WORKSPACE>` and `<TMP>`, and for OpenCode the real `XDG_DATA_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` that the run keeps (OpenCode saves truncated tool output under `<data>/opencode/tool-output/`) become `<DATA_HOME>`, `<STATE_HOME>` and `<CACHE_HOME>`, everywhere, in plain, `/private`, JSON-escaped and percent-encoded forms. An XDG directory that is the home directory or above it is never passed, so the home path itself stays visible to the scan. The scanner runs on the sanitized text and also scans decoded variants (percent-decoding, `\u00xx` and `\/` escapes, repeated up to six times); text still changing after that is reported as an `excessive-encoding` finding, so it is withheld too.
- **Every child process gets a matching `PWD`.** `with_pwd` is the one place that builds a child env; a test checks that each `subprocess` launch in `evals/` (the version probe, the runners, `git`, the judge) uses it.
- **Tokens.** Claude: `usage` of the final `result` event (input, output, cache creation, cache read). OpenCode: the sum of every category over all `step-finish` events. Neither figure is a billing number.
